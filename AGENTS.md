# AGENTS.md

Rules for every AI agent working in this repository (Claude Code, Codex, Cursor, Copilot, and others).
Project: Gateway7, the Modular LLM Gateway of team 7 in the ITPD course.

The course requirements are routed from [`SKILL.md`](https://github.com/inno-itpd/itpd/blob/main/SKILL.md); read the rule and the current week's assignment before you change or check anything they cover.
Do not rely on memory.
If a rule is not in the course repository, say so.

## Layout

- `gateway7/` is the gateway package: `app.py` and `openai_api.py` serve HTTP, `auth.py` checks client tokens and model allowlists, `pipeline.py` runs the middleware chain, `providers.py` holds the provider adapters, `models.py` and `plugin_api.py` are the plugin contract, `config.py` and `loader.py` load configuration and middleware, `metrics.py` exports Prometheus metrics, and `cli.py`, `scaffold.py` and `offline.py` are the `gateway7` CLI.
- `gateway7/plugins/` holds the reference middleware; a new built-in middleware goes here, and a company plugin goes in its own package generated by `gateway7 plugin init` (see `docs/authoring.md`).
- `tests/` holds the pytest suite as `tests/test_<area>.py`; add a test to the file of the area it checks.
- `demo/` is the synthetic provider and the scripted demonstration, `examples/` holds the sample plugins the plugin guide uses, and `config/` holds the YAML configuration for each provider and the demo.
- `monitoring/` holds the Prometheus configuration and Grafana provisioning used by `compose.yaml`.
- `scripts/` holds the smoke scripts the Python workflow runs.
- `docs/` holds the maintained documentation published as the site: guides, product vision, plan, risks, decisions, architecture in `docs/architecture/`, research in `docs/research/`, and the glossary in `docs/glossary.md`.
  A new page is also added to `nav` in `mkdocs.yml` and to the list in `docs/README.md`.
- `docs-build/` holds the site hooks, the generated-site check and the locked Mermaid asset.
- `reports/week-NN/` holds each week's evidence: report, meeting script and report, AI usage.
- `.github/` holds the workflows, the issue forms and the pull request template.
- `.claude/agents/` holds the agent definitions used in [Roles](#roles); `.agents-log.md` is the local agent log and is not committed.

## Checks

Run the checks your change touches before you push; CI runs them again on pull requests and pushes to `main`.

| Check | Local command | CI workflow |
| --- | --- | --- |
| Python format, lint, types, tests, demo, wheel | `uv run --locked ruff format --check gateway7`, `uv run --locked ruff check gateway7`, `uv run --locked mypy gateway7`, `uv run --locked pytest -q`, `uv run --locked python -m demo.run`, `uv build --wheel` | `.github/workflows/python.yml`, which also builds and checks the Compose stack |
| Markdown | `npx markdownlint-cli2 "**/*.md"` | `.github/workflows/markdown.yml` |
| Links | `lychee --no-progress --max-concurrency 2 --accept 200,206,429,503 './**/*.md'` (needs the network) | `.github/workflows/lychee.yml` |
| Documentation site | `mkdocs build --strict` and `python docs-build/check_site.py` in the docs environment from `CONTRIBUTING.md` | `.github/workflows/docs.yml` |

## Conventions

- Commit messages, branch names and pull requests follow [Git](#git); `CONTRIBUTING.md` records the same rules for members.
- Python targets 3.11+, is formatted by `ruff format` with a line length of 100, and passes `ruff check` and `mypy` with the settings in `pyproject.toml`.
- Markdown puts one sentence on a line and passes the rules in `.markdownlint-cli2.jsonc`.
- A link from `docs/` to a file outside it is a full GitHub URL, because the site serves only `docs/`.
- Identifiers such as `US-nn`, `DEC-nnn`, `CON-nn`, `BND-nn`, `TOS-nn`, `RISK-nn`, `ALT-nn`, `GAP-nn` and `VP-nn` appear in the heading of their own section or file, are never reused or renumbered, and a removed item is marked with a reason and date.
- A term from `docs/glossary.md` is used in the meaning the glossary gives; a change of meaning updates the glossary in the same pull request.

## Do Not Edit

- `CHANGELOG.md` released sections: edited only when a member cuts a release; during a sprint a change adds its line to `[Unreleased]` only, because a released section describes a tag that already exists.
- `reports/week-NN/` of a finished week: not rewritten after its week, because it is evidence that was submitted; corrections go into the current week's report.
- `docs/decisions.md` entries and `reports/week-NN/meeting-report.md`: written only from a decision or meeting that actually happened, with the source a member gives, because an agent cannot know what the Customer or the team decided.
- `.github/workflows/`: changed only in its own pull request, with every action pinned to a full commit SHA and its version comment, so a broken gate cannot hide inside another change.
- `uv.lock`, `requirements-docs.txt` and `docs-build/package-lock.json`: regenerated only by the commands in `CONTRIBUTING.md`, never edited by hand, because the hashes must match the resolver's output.
- `LICENSE` and `ATTRIBUTION.md`: changed only by a team decision, because they state the project's legal terms.
- `.env` and any file with a real key or token: never created or committed; `.env.example` holds placeholder names only.

## Roles

- **Orchestrator** only dispatches tasks to other agents.
  It never reads or edits files, runs commands, or does the task itself.
  For every task it runs PRE through Formater, delegates to the executing agent, then runs POST through Formater.
- **Formater** owns the [Workflow](#workflow) checks and all git work.
- **TechLead** owns the architecture (`docs/architecture/`, ADRs), picks skills for the stack, splits code work into tasks for developer agents, and reviews every code change.
  No code change passes POST without TechLead's `APPROVED`.
- **Executing agents** do the task within the constraints Formater set in PRE.

Tools without subagents (for example Codex) play all three roles in sequence, but keep the steps separate: PRE, then the task, then POST.

## Workflow

Every task goes through three steps.

### PRE: before starting

1. Add a log entry (see [Log](#log)): who does the task, what it is, which files it touches.
2. Check the task against the course rules: the artifact is in its final location (`docs/` for maintained documentation, `reports/week-NN/` for weekly evidence), no private data, one change per pull request.
3. Check git: the current branch is not `main`, and the branch name follows [Git](#git).
   Create the branch if needed.
4. State the constraints and acceptance criteria.
   If the task breaks a rule, stop with `BLOCKED` and the reason.

### POST: after finishing

1. Check the result against the PRE criteria and the [checklist](#checklist).
2. Add a log entry: what was done, changed files (`git status`, `git diff --stat`), verdict.
3. Verdict: `APPROVED`, or `CHANGES REQUIRED` with each violation as file:line, rule, fix.
   Fix everything and run POST again.
4. Record AI usage in `reports/week-NN/ai-usage.md`: tool and what it was used for.
   Leave the team's assessment of the output as `TODO`; never invent it.

### Git

- Branch names: `<issue-number>-<short-lowercase-description>`, such as `93-glossary-agents-md`.
- Never commit or push directly to `main`.
  Every change goes through a pull request.
- One pull request, one change, closing its task with one `Closes #N` line.
- Commit messages: imperative English subject, at most 72 characters, optional body.
  Add the co-author trailer your tool requires.
- Pull requests fill in [.github/pull_request_template.md](.github/pull_request_template.md).
- Never rewrite shared history (`rebase`, `push --force`, `reset --hard`), except to remove leaked secrets.
- A commit, `git push`, creating a pull request, and merging need explicit confirmation from the user.

## Checklist

- The change follows the rule `SKILL.md` routes its artifact to, and the week report covers every item the week's assignment lists.
- Files are where [Layout](#layout) puts them, and no file from [Do Not Edit](#do-not-edit) changed outside its condition.
- The [Checks](#checks) for the changed files pass.
- References between artifacts use identifiers, and identifiers follow [Conventions](#conventions).
- No private material: real names, university emails, recording links or timecodes, secrets, `.env`, large binaries.
- All Markdown links resolve; every exclusion in `.lycheeignore` is justified.
- No filler: a sentence that could be pasted into another team's report unchanged is a finding.

## Log

Keep the log in `.agents-log.md` in the repository root.
Entry format:

```text
## <YYYY-MM-DD HH:MM> <PRE|POST|GIT> - <short task name>
- Agent: <tool or user>
- Branch: <name>
- Files: <list>
- Verdict: <OK | BLOCKED | APPROVED | CHANGES REQUIRED>
- Notes: <list or None>
```

## Limits

- Do not invent research findings, meeting content, Customer decisions, or team assessments; check and format only.
- Report to the user briefly: verdict and findings, no retelling of the work.
