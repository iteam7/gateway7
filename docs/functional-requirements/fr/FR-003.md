# FR-003: Run Company Middleware From Configuration

- **Status:** Active
- **Traces to:** [`US-03`](https://github.com/iteam7/gateway7/issues/32), [`DEC-010`](../../decisions.md#dec-010), [`DEC-016`](../../decisions.md#dec-016), [`ADR-001`](../../architecture/adr/ADR-001.md), [`ADR-002`](../../architecture/adr/ADR-002.md)
- **Containers:** `gateway`

## Behavior

When an operator lists an installed company middleware module in the configuration and restarts the gateway, the gateway shall run it without any change to the gateway's own code.

The gateway shall run the configured middleware list in its order on the request and in the reverse order on the response.

When the configuration lists a middleware whose module is missing, the gateway shall exit at startup and shall name that middleware instance, even when the instance is disabled.

## Acceptance Criteria

### AC-01

Given the sample plugin copied to `company_plugins/sample.py` and added to the middleware list after a restart, when a client sends `ping`, then the provider receives `ping[checked-by-sample]` and `git status` lists only the new module and the configuration file.

### AC-02

Given two instances of the sample plugin with markers `[A]` and `[B]` in the list `[mask, alpha, beta]`, when a client sends `ping`, then the provider receives `ping[A][B]` and the client's answer ends with `[B][A]`.

### AC-03

Given a configuration that lists module `company_plugins.does_not_exist`, enabled or disabled, when the gateway starts, then it exits with a non-zero status and its output names the instance or the module.
