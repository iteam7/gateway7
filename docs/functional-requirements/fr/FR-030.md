# FR-030: Try A Plugin Through A Local Synthetic Gateway

- **Status:** Active
- **Traces to:** [Repository owner task #297](https://github.com/iteam7/gateway7/issues/297), [ADR-012](../../architecture/adr/ADR-012.md)
- **Containers:** `gateway`

## Behavior

When an author starts a plugin project's development command, the gateway shall provide a loopback-only gateway and synthetic upstream using that project's policy and settings without requiring a provider account.
The command shall report the local address and usable synthetic client instructions and shall leave the project's files unchanged.
The development process shall not inherit real provider or gateway credentials from the invoking environment.
When startup fails or the author interrupts the command, it shall stop and reap its owned development processes and close their listening sockets.

## Acceptance Criteria

### AC-01

Given an installed gateway wheel and a generated project outside the checkout, when the author runs `gateway7 plugin dev PROJECT`, then the reported loopback address accepts an authenticated synthetic request that demonstrates the project's transformation or denial without a paid provider request.
The selected ports do not require the author to reserve fixed ports or create another configuration file.

### AC-02

Given a running development environment, when it is interrupted, then its child process exits, the gateway and upstream ports close, and the project files remain unchanged.
The same cleanup holds after a plugin startup failure, and a plugin import cannot read a synthetic secret set only in the invoking environment.
