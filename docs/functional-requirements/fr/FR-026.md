# FR-026: Inspect Protected Client Activity And Retain Bounded History

- **Status:** Active
- **Traces to:** [Repository owner task #295](https://github.com/iteam7/gateway7/issues/295), [FR-012](FR-012.md), [FR-019](FR-019.md), [ADR-010](../../architecture/adr/ADR-010.md)
- **Containers:** `gateway`

## Behavior

The operator console shall report client activity using identity, key, model, last-seen time, terminal outcomes, denials and latency without retaining conversation content.
Current active requests and remaining rate allowance shall be visible separately from durable accounting and budget state.
History shall support client/model filters, aware UTC intervals with an inclusive start and exclusive end, time buckets and bounded pagination.
CSV export shall stream selected rows without first materializing the entire history and shall escape spreadsheet formulas.
An administrator shall configure history retention, and cleanup shall remove expired detail while preserving required budget accounting.
Client search and pagination shall support status, owner labels and tags.

## Acceptance Criteria

### AC-01

Given completed, denied, failed and streamed client requests across an interval boundary, when an authorized operator filters history, then it identifies the correct client/key/model and terminal outcomes, excludes the end boundary and includes the start boundary, and reports no provider tokens for a request denied before forwarding.

### AC-02

Given several pages of account and history rows and expired detail, when pages, filters, retention and CSV export are exercised, then page limits hold, selected rows remain correct, expired detail is removed, current budget state remains intact and cancellation closes an unfinished export without leaking credentials or message content.
