# FR-028: Back Up And Restore Managed State Offline

- **Status:** Active
- **Traces to:** [Repository owner task #295](https://github.com/iteam7/gateway7/issues/295), [FR-021](FR-021.md), [FR-024](FR-024.md), [FR-027](FR-027.md), [ADR-010](../../architecture/adr/ADR-010.md)
- **Containers:** `gateway`

## Behavior

An operator with server access shall create a consistent, versioned private backup of managed state and restore a validated backup into an empty destination of the same backend.
Backup shall preserve client policies, named key and operator digests, encrypted provider settings, control revisions, audit, precise accounting, budgets, unresolved reservations and retained legacy observations.
The backup shall exclude the server encryption key and raw credentials.
The file shall carry an integrity check and private filesystem permissions, and invalid or incompatible files shall fail before destructive changes.
An active database owner or a nonempty restoration destination shall prevent the offline operation.
The runbook shall explain restoring the separately held encryption key and verifying client permissions, credential revocation and accounting after restoration.
Cross-backend SQLite-to-PostgreSQL transfer remains outside this behavior.

## Acceptance Criteria

### AC-01

Given managed accounts with named keys, revoked access, provider configuration, audit entries and budget reservations, when a stopped store is backed up and restored into an empty same-backend destination, then restart preserves these records and enforcement, including unavailable revoked credentials and unresolved budget consumption.

### AC-02

Given a corrupted file, incompatible version, active owner or nonempty destination, when backup or restoration is attempted, then it fails safely without overwriting managed state or printing credentials and creates no world-readable private artifact.
