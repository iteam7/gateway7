# FR-012: Report Each Developer's Model Usage Over A Period

- **Status:** Active
- **Traces to:** [US-13](https://github.com/iteam7/gateway7/issues/141), [ADR-003](../../architecture/adr/ADR-003.md)
- **Containers:** `gateway`

## Behavior

When an operator requests a usage report for a UTC interval, the gateway shall report attempted provider-call counts and provider-reported input and output token totals, grouped by the configured client identity and the model selected for the provider call.
The interval shall include calls started at its start and exclude calls started at its end.
Client identity shall come from authentication, rather than from the prompt or middleware-editable content.

When a request is denied before forwarding, the gateway shall add no provider call or tokens to that report.
When a provider call completes but a response-side policy blocks delivery, the gateway shall retain that call and its reported usage in the report.
When a provider call supplies no usage, whether it succeeds or fails, the gateway shall count the attempted call and mark its token usage as unavailable instead of treating missing usage as zero.
For a group containing such calls, the gateway shall distinguish known token totals from the number of calls with unavailable usage.

The gateway shall exclude prompts, answers, client tokens and provider credentials from the report, and shall not add client identities or request identifiers as metric labels to expose this report.

## Acceptance Criteria

### AC-01

Given authenticated clients `client-a` and `client-b`, and a report interval from `2026-11-01T00:00:00Z` inclusive to `2026-11-02T00:00:00Z` exclusive, make these calls with a recording provider:

| Client | Model | Call start | Provider input tokens | Provider output tokens |
| --- | --- | --- | --- | --- |
| `client-a` | `model-a` | `2026-11-01T00:00:00Z` | 10 | 4 |
| `client-a` | `model-a` | `2026-11-01T12:00:00Z` | 6 | 2 |
| `client-a` | `model-b` | `2026-11-01T13:00:00Z` | 8 | 3 |
| `client-b` | `model-a` | `2026-11-01T14:00:00Z` | 5 | 1 |
| `client-b` | `model-a` | `2026-11-02T00:00:00Z` | 20 | 9 |

When the operator reads the report, then `client-a`/`model-a` has 2 calls, 16 input tokens and 6 output tokens; `client-a`/`model-b` has 1 call, 8 input tokens and 3 output tokens; and `client-b`/`model-a` has 1 call, 5 input tokens and 1 output token.
The call at the interval's end contributes nothing to these totals.

### AC-02

Given an authenticated request denied by a request-side policy and another whose provider returns 7 input tokens and 2 output tokens before a response-side policy blocks delivery, when the report is read for both calls' interval, then the provider recorded only the second call, and the report adds exactly 1 attempted call, 7 input tokens and 2 output tokens.

### AC-03

Given one call returning 4 input tokens and 1 output token and one failed call with no reported usage for the same client and model, when the operator reads their interval's report, then it shows 2 attempted calls, known totals of 4 input tokens and 1 output token, and 1 call with unavailable token usage.
It does not describe the known totals as the complete usage of both calls.

### AC-04

Given calls containing synthetic prompt text, answer text, a client token and a provider credential, when the report is searched, then none of those values appears.
When `GET /metrics` is read after the same calls, then no client identity or request identifier has been added as a metric label.
