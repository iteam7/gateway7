# FR-011: Name The Middleware That Failed Or Slowed A Request

- **Status:** Active
- **Traces to:** [`US-12`](https://github.com/iteam7/gateway7/issues/140), [`DEC-014`](../../decisions.md#dec-014), [`ADR-002`](../../architecture/adr/ADR-002.md)
- **Containers:** `gateway`

## Behavior

When a middleware instance raises an error or returns an invalid result, the gateway shall write a log entry carrying the request's identifier, the instance name, the phase and the outcome `plugin_error`, and shall return the `plugin_error` response carrying the same request identifier.

When such a failure passes through an outer middleware instance, the gateway shall write that instance's own entry, with the same outcome and phase `response`, after the failing instance's entry.

When a middleware instance exceeds its configured hook time budget, the gateway shall write a log entry carrying the request's identifier, the instance name, the phase and the outcome `timeout`, and shall return the `timeout` response carrying the same request identifier.

When a middleware instance finishes a phase, the gateway shall write a log entry carrying the request's identifier, the instance name, the phase and the time that instance spent in it.

The gateway shall write no prompt, answer, client token or provider credential in these entries.

## Acceptance Criteria

### AC-01

Given a chain of two middleware instances whose second raises an error on the request phase, when a chat request is sent, then the client receives HTTP 500 with code `plugin_error`, and the log has an entry with that response's `request_id`, the second instance's name, phase `request` and outcome `plugin_error`, written before any entry for the first instance under that `request_id`.

### AC-02

Given a middleware instance that sleeps longer than `limits.hook_timeout_seconds`, when a chat request is sent, then the client receives HTTP 504 with code `timeout`, and the log has an entry with that response's `request_id`, the instance's name and outcome `timeout`.

### AC-03

Given a chain of two middleware instances that both succeed, when a chat request is sent, then the log has, under the response's `request_id`, a `continue` entry for phase `request` and a `complete` entry for phase `response`, each with a `duration_ms` value, for each instance.

### AC-04

Given requests carrying a synthetic client token and synthetic message text, when the gateway's log is searched, then neither the token nor the text appears.
