# FR-014: Expose Each API Request's Quality Signal To The Observability Backend

- **Status:** Active
- **Traces to:** [US-15](https://github.com/iteam7/gateway7/issues/175), [SLI-01](../../observability.md#sli-01)
- **Containers:** `gateway`

## Behavior

When telemetry collection is enabled for an environment, the gateway shall push, for each API request it completes, one structured log record and one request-duration histogram observation to that environment's observability backend over OTLP/HTTP, tagged with the environment's name.

The log record shall carry the request identifier returned to the client, the fixed route name, the outcome, the HTTP status, the gateway's fixed error code and the request duration in milliseconds, and the histogram observation shall carry the same duration with only the route and outcome labels.

The gateway shall not record health-check or metric-scrape requests, and shall not put request or response content, client names, credentials, model names or network addresses into either signal.

When telemetry collection is disabled or not configured, the gateway shall start no exporter and send no signal; when it is enabled without an environment name or backend endpoint, the gateway shall refuse to start.

## Acceptance Criteria

### AC-01

Given collection enabled for `staging`, when a client sends one successful chat request and one chat request for a model it is not allowed to use, then the staging organization's log query returns exactly one record for each `X-Request-ID`, the failed one with route `openai_chat`, outcome `client_error`, status `403` and error code `model_forbidden`, and each record's `duration_ms` equals the duration recorded by the histogram for that request.

### AC-02

Given the same traffic, when the [SLI-01](../../observability.md#sli-01) query runs against the staging organization within one minute of the failed response, then it returns a separate `client_error` series for `openai_chat` with a numeric P95.

### AC-03

Given synthetic prompt text and client tokens in the requests, when the exported log records and histogram points are inspected, then neither contains the prompt text, a token, the client name or the model name, and health-check and metric-scrape requests produce no exported point.

### AC-04

Given `TELEMETRY_ENABLED` unset or `false`, when the gateway serves requests, then it creates no exporter; given `TELEMETRY_ENABLED=true` without `GATEWAY7_ENVIRONMENT` set to `staging` or `production` or without an OTLP endpoint, then startup fails with a configuration error.
