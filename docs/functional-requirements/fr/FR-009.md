# FR-009: Expose Request And Middleware Metrics

- **Status:** Active
- **Traces to:** [`DEC-014`](../../decisions.md#dec-014)
- **Containers:** `gateway`

## Behavior

When the gateway handles requests, it shall expose on `GET /metrics` the counts and durations of HTTP requests by route and status, of provider calls by provider and outcome, and of each middleware's own work by instance, phase and outcome.

The gateway shall record exactly one provider-call observation for each attempted provider call and none for a request rejected before forwarding.

The gateway shall use no prompt, answer, policy term, credential, request identifier or client name as a metric label.

## Acceptance Criteria

### AC-01

Given one allowed chat request and one request denied by a request-side policy, when `/metrics` is read, then `gateway7_provider_calls_total` has increased by exactly one and `gateway7_http_requests_total` shows one `chat` request with status `200` and one with status `403`.

### AC-02

Given requests carrying a synthetic client token and synthetic message text, when `/metrics` is read, then neither the token, the text nor the client's name appears anywhere in the output.
