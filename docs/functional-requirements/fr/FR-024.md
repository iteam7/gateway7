# FR-024: Enforce User And Model Usage Budgets

- **Status:** Active
- **Traces to:** [Repository owner task #295](https://github.com/iteam7/gateway7/issues/295), [FR-012](FR-012.md), [FR-019](FR-019.md), [ADR-010](../../architecture/adr/ADR-010.md)
- **Containers:** `gateway`

## Behavior

An administrator shall configure model input/output prices and user/model token or estimated-cost budgets for UTC day and month periods through the console.
Amounts shall use exact integer monetary units and capture the applicable price revision per attempt.
Warning rules shall expose threshold state without denying requests.
Hard rules shall atomically reserve finite input/output and cost bounds before forwarding, sharing the allowance across the user's keys and concurrent calls.
A request that cannot be bounded or priced for an applicable hard rule shall be denied before provider invocation.
Terminal provider usage shall settle each reservation once; unknown usage, cancellation or process interruption shall remain visible and shall not silently release uncertain consumption as zero.
Detailed-history retention shall not reset current budget totals or unresolved reservations.

## Acceptance Criteria

### AC-01

Given concurrent requests through different keys for one user and an allowance sufficient for only one reservation, when both request forwarding, then at most one reaches the provider under the hard rule.
Equivalent tests cover user and model scopes, token and cost amounts, and day/month boundaries.

### AC-02

Given warning and hard rules, a pricing update, a terminal attempt with partial usage and an unresolved interrupted attempt, when accounting is inspected after restart, then the warning does not deny traffic, the hard rule uses captured prices, known directions remain separate from unknown usage, and uncertain reservations still constrain new calls.
