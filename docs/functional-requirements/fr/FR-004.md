# FR-004: Block Or Log A Flagged Request

- **Status:** Active
- **Traces to:** [`US-04`](https://github.com/iteam7/gateway7/issues/33), [`DEC-016`](../../decisions.md#dec-016), [`ADR-002`](../../architecture/adr/ADR-002.md)
- **Containers:** `gateway`
- **Changed:** 2026-11-06 — Add the denying instance to the client error and the bounded unsupported action identifier to startup output, reconciling AC-01 and AC-03 with the unchanged [US-04](https://github.com/iteam7/gateway7/issues/33) criteria; the previous wording omitted those diagnostic fields.

## Behavior

When a content-policy middleware configured with action `block` matches one of its terms in a request, the gateway shall return the safe `policy_denied` error naming the denying configured middleware instance in `error.middleware` and shall make no provider call.

When the same middleware is configured with action `log` and matches a term, the gateway shall forward the request unchanged and shall log the request identifier, the middleware instance, the direction, the action and the match count, without the matched term or the message text.

When a content-policy middleware is configured with an action other than `block`, `log` or `redact`, the gateway shall exit at startup and shall name the instance.
When that unsupported action is an identifier of at most 32 lowercase ASCII letters, digits, underscores or hyphens starting with a letter, the startup diagnostic shall also name the action.
Malformed, non-string, oversized or control-containing action values shall remain redacted, and the diagnostic shall never include terms, replacement text or arbitrary validation input.

## Acceptance Criteria

### AC-01

Given the content policy with term `BLOCK-ME-TEST` and action `block` on the request phase, when a client sends a message containing `BLOCK-ME-TEST`, then the client gets HTTP 403 with error code `policy_denied` and `error.middleware` naming the denying instance on either chat API, and the provider records no request.

### AC-02

Given the same policy with action `log`, when a client sends the same message, then the provider receives it unchanged and the gateway log has one policy entry naming the instance and the action that contains neither `BLOCK-ME-TEST` nor the message text.

### AC-03

Given the policy configured with action `explode`, when the gateway starts, then it exits with a non-zero status before serving requests and its output names the instance and the unsupported action `explode` without policy terms or other settings.
