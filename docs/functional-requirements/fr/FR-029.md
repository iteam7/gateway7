# FR-029: Inspect A Plugin Project Before Installation

- **Status:** Active
- **Traces to:** [Repository owner task #297](https://github.com/iteam7/gateway7/issues/297), [ADR-012](../../architecture/adr/ADR-012.md)
- **Containers:** `gateway`

## Behavior

When an author inspects a plugin project, the gateway shall report its module, middleware API version, settings schema, declared profiles, available hooks and resolvable distribution provenance.
The report shall distinguish declarations and hook presence from behavior verified by synthetic cases.
Inspection shall use the selected project's metadata and shall not resolve provider or gateway credentials or initialize a provider.
When project loading fails, the gateway shall report a core-authored diagnostic code and safe location without configured input values or arbitrary plugin exception text.

## Acceptance Criteria

### AC-01

Given a generated project outside the gateway checkout, when the author runs `gateway7 plugin inspect PROJECT --json` from the installed gateway environment, then the report identifies middleware API 2, its settings fields, its declared profiles and available hooks, and exits with code 0 without provider credentials.
A local uninstalled module can have unknown distribution provenance without making a valid descriptor invalid.

### AC-02

Given a plugin with an invalid descriptor, invalid settings or an import failure containing a synthetic secret, when it is inspected, then the command exits with code 2 and its output includes a safe diagnostic code while excluding the secret and raw exception text.
An unsupported API version reports the expected version and the actual numeric version safely.
