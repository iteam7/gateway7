# FR-001: Answer With The Server-Held Provider Key

- **Status:** Active
- **Traces to:** [`US-01`](https://github.com/iteam7/gateway7/issues/30), [`CON-04`](../../product-vision.md#con-04), [`DEC-011`](../../decisions.md#dec-011), [`ADR-001`](../../architecture/adr/ADR-001.md), [`ADR-003`](../../architecture/adr/ADR-003.md), [`ADR-004`](../../architecture/adr/ADR-004.md), [`ADR-005`](../../architecture/adr/ADR-005.md)
- **Containers:** `gateway`
- **Changed:** 2026-10-30: linked the guarded provider-stream and agent extension in ADR-005; the existing behavior and criterion identifiers are retained.

## Behavior

When an authorized client sends a chat request without any provider credential, the gateway shall forward it to the configured provider with the provider key read from the server's environment and shall return the provider's answer.

When the configured provider key variable is missing at startup, the gateway shall exit before serving requests and shall name the missing setting without printing any secret value.

## Acceptance Criteria

### AC-01

Given the fake provider and a synthetic provider key in the server environment, when a client posts the README chat request with no provider credential, then the client gets HTTP 200 with the fake provider's answer and the provider's recorder reports `key_accepted: true`.

### AC-02

Given a configuration whose `provider.key_env` variable is unset, when the gateway starts, then it exits with a non-zero status, its output names that variable, and no service answers on the configured port.
