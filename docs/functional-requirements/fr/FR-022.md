# FR-022: Migrate Managed Accounts From SQLite To PostgreSQL

- **Status:** Dropped
- **Traces to:** [Repository owner PostgreSQL clarification](https://github.com/iteam7/gateway7/issues/288), [US-07](https://github.com/iteam7/gateway7/issues/36), [FR-021](FR-021.md), [FR-019](FR-019.md), [ADR-009](../../architecture/adr/ADR-009.md)
- **Containers:** `gateway`
- **Dropped:** 2026-11-16: The [repository owner clarified](https://github.com/iteam7/gateway7/issues/288) that the application has not been run and there is no existing data to transfer; PostgreSQL is used from the first deployment, as recorded in [ADR-009](../../architecture/adr/ADR-009.md).

## Behavior

The proposed transfer between SQLite and PostgreSQL was withdrawn before deployment.
This requirement specifies no active product behavior or available command.
Its identifier and acceptance-criteria anchors remain reserved for traceability.

## Acceptance Criteria

These criteria describe the withdrawn proposal; they are historical, unimplemented checks and are not part of the current product contract.

### AC-01

Given a stopped SQLite source containing enabled, suspended, revoked and deleted clients, provider usage for several days and models, and an original accounting start timestamp, when the operator runs migration into an empty PostgreSQL target, then the source is unchanged and the PostgreSQL gateway retains the profiles, working credentials, revocations, reserved deleted identities, exact usage aggregates and accounting start timestamp after restart.
No raw client token is needed for migration or stored in the target.

### AC-02

Given an active source owner, a corrupt source, an incompatible source schema, an initialized target, an incompatible target schema or an active target owner, when migration runs, then it fails safely and preserves the source and any existing target account and usage state.
A transaction failure leaves no initialized target registry or partially imported account subset.

### AC-03

Given a private PostgreSQL connection string in an explicitly named environment variable, when migration succeeds or fails, then command output and diagnostics contain neither that string nor its password, client token values, credential digests or private account contents.
A missing or invalid named connection setting fails with a nonzero exit status.

### AC-04

Given an existing SQLite store and a PostgreSQL configuration selected for normal gateway startup, when startup runs without an explicit migration, then it neither reads that SQLite file nor imports or resets its state.
If the selected PostgreSQL store is unavailable or incompatible, startup fails rather than silently switching to SQLite.
