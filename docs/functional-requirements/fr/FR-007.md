# FR-007: Check A Middleware Against Synthetic Fixtures Offline

- **Status:** Active
- **Traces to:** [`US-08`](https://github.com/iteam7/gateway7/issues/37), [`ADR-002`](../../architecture/adr/ADR-002.md)
- **Containers:** `gateway`

## Behavior

When a plugin author runs `gateway7 plugin test` with a configuration and a fixtures file, the gateway shall run each fixture through the configured middleware against an in-memory fixture provider, without resolving any provider key or contacting a provider.

The gateway shall report, for each fixture, the expected and actual values of every check and whether the check passed.

The command shall exit with code 0 when every fixture matches, 1 when at least one check differs, and 2 when the configuration or fixtures are invalid or the run fails.

## Acceptance Criteria

### AC-01

Given the generated starter project and its unchanged `fixtures.json`, when the author runs `gateway7 plugin test --config company_mask/gateway.yaml --fixtures company_mask/fixtures.json`, then every case is reported as passed and the command exits with code 0.

### AC-02

Given a copy of `fixtures.json` with one expected response changed, when the same command runs on the copy, then the report marks that check failed with both the expected and the actual text, and the command exits with code 1.

### AC-03

Given a fixtures file with an unknown field, when the command runs, then it exits with code 2 and makes no provider call.
