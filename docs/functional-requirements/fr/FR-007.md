# FR-007: Check A Middleware Against Synthetic Fixtures Offline

- **Status:** Active
- **Traces to:** [`US-08`](https://github.com/iteam7/gateway7/issues/37), [`ADR-002`](../../architecture/adr/ADR-002.md), [Repository owner task #297](https://github.com/iteam7/gateway7/issues/297), [ADR-012](../../architecture/adr/ADR-012.md)
- **Containers:** `gateway`
- **Changed:** 2026-11-17, the owner's task #297 replaces separate configuration/fixture flags and schema-1 fixtures with one project contract and profile-aware schema-2 fixtures.

## Behavior

When a plugin author runs `gateway7 plugin test` for a project, the gateway shall resolve its configuration and schema-2 fixtures from the project's metadata and run each case through the corresponding configured middleware profile against a synthetic provider, without resolving any provider key or contacting a provider.

The gateway shall report, for each fixture, the expected and actual values of every check and whether the check passed.
The report shall identify the profiles actually exercised and shall distinguish unsupported-profile checks from successful supported-profile execution.

The command shall exit with code 0 when every fixture matches, 1 when at least one check differs, and 2 when the configuration or fixtures are invalid or the run fails.

## Acceptance Criteria

### AC-01

Given the generated starter project and its unchanged `fixtures.json`, when the author runs `gateway7 plugin test company_mask` or runs `gateway7 plugin test` inside that project, then every case is reported as passed and the command exits with code 0.

### AC-02

Given a copy of `fixtures.json` with one expected response changed, when the same command runs on the copy, then the report marks that check failed with both the expected and the actual text, and the command exits with code 1.

### AC-03

Given a fixtures file with an unknown field, when the command runs, then it exits with code 2 and makes no provider call.

### AC-04

Given guard and redaction presets, when their profile matrices run, then Chat, tools and native cases preserve protected identifiers and provider usage, request denials make zero provider calls, request-only early cases run their preparation hooks, and response-dependent early cases reject before provider work.
Missing required hooks never cause policy skipping or a silent delivery-mode fallback.
