# FR-023: Authorize Named Operators By Role

- **Status:** Active
- **Traces to:** [Repository owner task #295](https://github.com/iteam7/gateway7/issues/295), [FR-021](FR-021.md), [ADR-010](../../architecture/adr/ADR-010.md), [ADR-013](../../architecture/adr/ADR-013.md)
- **Containers:** `gateway`
- **Changed:**
  - 2026-11-23: linked ADR-013 for browser-session authentication; the named bearer and role criteria remain active.

## Behavior

The gateway shall authenticate named operator credentials and associate each with an administrative or read-only role.
Administrative operators shall manage operator credentials, roles and expiration through the protected console.
Read-only operators shall inspect permitted account, model, usage and audit data without changing state or obtaining newly generated credentials.
Credentials shall be represented by digests in managed storage, and expiration or revocation shall prevent subsequent access.
The server-configured bootstrap operator shall remain available as an identified recovery capability.
Mutation authorization shall be checked against current role and credential state after request-body delivery, in addition to the existing authentication, revision and browser-origin checks.

## Acceptance Criteria

### AC-01

Given an administrator, a read-only operator and an expired or revoked operator credential, when each requests protected data and mutation routes, then the administrator has its permitted actions, the read-only operator can read but receives an authorization denial on every write, and the expired or revoked credential cannot authenticate.
No state, log, audit record or error contains the credential value or digest.

### AC-02

Given an operator whose write request is waiting for its body, when another administrator revokes that credential or changes it to read-only before the body completes, then the pending mutation is denied and managed state remains unchanged.
