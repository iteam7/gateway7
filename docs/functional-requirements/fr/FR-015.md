# FR-015: Record Privacy-Safe Chat Task Events For Product Analytics

- **Status:** Active
- **Traces to:** [US-14](https://github.com/iteam7/gateway7/issues/174), [ADR-006](../../architecture/adr/ADR-006.md)
- **Containers:** `gateway`

## Behavior

When analytics is enabled, the gateway shall enqueue one `chat_started` event on receipt of a request on either chat API and one `chat_completed` event after its completed response, failure or cancellation, using the [event registry](../../analytics.md#the-events).
The events shall share a randomly generated task identifier and shall carry only the documented typed fields.
The gateway shall export events asynchronously to the configured environment's OpenPanel project without forwarding conversation content, client identity or request headers.

Collection shall be disabled by default.
When enabled, missing or invalid environment, destination or credentials shall prevent startup without echoing private values.
The server shall own the event source; production shall require `source=web`, and staging alone shall accept `source=smoke` or `source=usability-test`.
The environment's credential shall select its isolated backend project.

Delivery shall use a bounded queue and a background worker; queue overflow, export failure or an incomplete shutdown flush shall drop pending events without changing an HTTP response.
No redirect shall forward the analytics credentials, and no retry shall duplicate an uncertain delivery.

## Acceptance Criteria

### AC-01

Given analytics enabled for staging and a reachable collector, when successful and denied requests use both chat APIs, then the collector receives each documented start and completion with the returned task identifier, the fixed route and the actual completion result; health checks, metric scrapes and model listings produce no product event.

### AC-02

Given synthetic conversation text, model names, client tokens and extra source headers, when the exported payloads are inspected, then only fields in the registry are present and the source equals the deployment configuration.

### AC-03

Given production analytics configured with `source=smoke` or `source=usability-test`, when startup is attempted, then startup fails before sending an event; given `ANALYTICS_ENABLED=false`, then no exporter client or worker is created.

### AC-04

Given an unavailable or slow analytics collector or more events than the bounded queue can hold, when a chat request finishes, then it retains its gateway response and the exporter neither blocks it nor retries an event; shutdown abandons a stuck delivery after its bounded drain.

### AC-05

Given HTTP 200 headers sent but the answer body send then fails or is cancelled, when the task completion is exported, then its outcome is a failure or cancellation and it does not increase the successful-task metric.
