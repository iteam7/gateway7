# FR-025: Manage The Live Provider And Effective Models

- **Status:** Active
- **Traces to:** [Repository owner task #295](https://github.com/iteam7/gateway7/issues/295), [FR-006](FR-006.md), [ADR-011](../../architecture/adr/ADR-011.md)
- **Containers:** `gateway`

## Behavior

An administrator shall inspect the selected provider, model catalog and explicit connection-test results, and shall update its configuration, default model, global permissions and credential through the console.
Provider credentials shall be persisted encrypted using a separately supplied server key and shall be excluded from state, logs, exports and audit diffs.
Candidate configuration shall pass the existing provider-origin, transport and model validation before publication.
Already-admitted requests shall retain their captured provider and policy while new requests use the committed replacement without restarting the gateway.
The console shall distinguish configured client permissions from the effective intersection with the global policy and shall expose a denied-default warning.
Aliases shall resolve to canonical models before authorization, and a configured permitted client default shall apply when the caller omits a model.
Connection tests shall be explicit operator actions with a timestamped sanitized result.

## Acceptance Criteria

### AC-01

Given a global policy allowing only model A and a client profile naming model B, when an operator inspects the client, then its configured list and empty effective permissions are distinct and a request for B is denied before provider work.
Canonical and alias requests apply the same effective permission boundary.

### AC-02

Given an in-flight request using one provider and a valid administrative provider change, when the change commits, then that request finishes through its original provider while a subsequent request uses the replacement.
Restart loads the committed configuration and encrypted credential; invalid candidates or stale revisions change neither stored nor running state.
