# FR-020: Inspect Clients And Middleware In A Read-Only Operator Console

- **Status:** Active
- **Traces to:** [Repository owner request, 2026-11-11](https://github.com/iteam7/gateway7/issues/257), [FR-019](FR-019.md), [ADR-003](../../architecture/adr/ADR-003.md)
- **Containers:** `gateway`

## Behavior

When operator access is configured, the gateway shall serve a read-only browser console with a public shell that contains no account, usage or middleware configuration data.

When a caller supplies the separate operator credential, the gateway shall provide a sanitized snapshot of configured clients, their enabled state, model permissions and limits, provider usage for the current process, and global and additional middleware chains.

The snapshot shall omit credentials, credential environment references, provider origins, conversations and plugin settings, including policy terms.
It shall distinguish known token usage from attempts with unknown usage and shall identify counters as process-lifetime values that reset on restart.

The console shall label configuration validation as a startup observation and middleware capabilities as registered hooks or declarations, without claiming live health or universal request compatibility.
Disabled middleware shall be identified as not instantiated.

The console shall hold its operator credential only in page memory and transmit it only through an authorization header to the same origin.
Disconnecting or leaving the page shall clear the credential and displayed operator data.

When operator access is absent, the console shell, assets and state endpoint shall return HTTP 404.
Operator responses shall prohibit caching, and console content shall use a content security policy that restricts scripts, styles and connections to the same origin.

The console shall provide no account, permission, limit or middleware mutation operation.
Configuration changes shall continue to require server-side validation, appropriate isolated middleware checks and restart.

## Acceptance Criteria

### AC-01

Given operator access is disabled, when the console shell, stylesheet, script or state endpoint is requested, then each returns HTTP 404 and exposes no configured operator data.
Given operator access is enabled, an unauthenticated caller can load only the static shell and assets, and missing, client, provider, duplicated, cookie or query credentials cannot obtain the state snapshot or trigger provider work.

### AC-02

Given enabled and suspended clients with different limits and additional policies, when an authenticated operator opens the console, then the displayed state matches those configured values, the effective client chains preserve the global baseline order, and disabled middleware has no fabricated runtime capabilities.
The snapshot contains no credentials, environment references, provider origin, conversation or plugin settings.

### AC-03

Given one provider attempt with known input/output usage and another with unknown usage, when the operator refreshes the console, then known totals and unknown attempt counts remain separate and the process-lifetime scope and restart reset are visible.
Provider completions are not presented as proof of successful downstream delivery or as monetary charges.

### AC-04

Given a console session, when the operator connects, refreshes, disconnects or leaves the page, then the credential appears in no URL, cookie or browser storage, and disconnecting clears the displayed data and prevents an outstanding response from restoring it.
Browser checks verify the rendered workspace and login/error/logout behavior with synthetic data, and the built wheel contains the HTML, stylesheet and script.

### AC-05

Given the operator console is available, when a mutation request is sent, then it cannot change accounts, limits, permissions or middleware.
The shell and operator state responses carry `Cache-Control: no-store`, and the rendered console loads no external scripts, styles or automatic network requests.
