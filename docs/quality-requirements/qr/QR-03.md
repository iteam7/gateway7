# QR-03: Keep Credentials And Message Text Out Of Gateway Output

No provider key, client token or message text appears in the gateway's logs, metrics or error responses.

- **Status:** Active
- **Characteristic:** Security
- **Sub-characteristic:** Confidentiality
- **Business importance:** High
- **Technical risk:** Medium

## Scenario

### Source

An operator or monitoring tool that reads the gateway's logs, its `/metrics` endpoint or its error responses.

### Stimulus

Clients send allowed, denied and failing chat requests that contain recognizable synthetic text, using a synthetic provider key and synthetic client tokens.

### Environment

The gateway holds one server-configured provider key, per [`CON-04`](../../product-vision.md#con-04), with client authentication enabled and the shipped middleware configured.

### Artifact

The gateway's log output, the `/metrics` exposition and the error bodies it returns.

### Response

The gateway shall report request identifiers, fixed outcome codes and durations without the credential values or the message text.

### Response Measure

After the runs, a search of the captured logs, the `/metrics` output and every error body finds zero occurrences of the synthetic provider key, each synthetic client token and each synthetic message.
