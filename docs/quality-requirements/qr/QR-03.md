# QR-03: Keep Credentials And Message Text Out Of Gateway Output

No provider key, client token or message text appears in the gateway's logs, metrics or error responses.

- **Status:** Active
- **Characteristic:** Security
- **Sub-characteristic:** Confidentiality
- **Business importance:** High
- **Technical risk:** Medium

## Scenario

### Source

An operator or monitoring tool that reads the gateway's logs, its `/metrics` endpoint or its error responses.

### Stimulus

Clients send allowed, denied and failing chat requests that contain recognizable synthetic text, using a synthetic provider key and synthetic client tokens.

### Environment

The gateway holds one server-configured provider key, per [`CON-04`](../../product-vision.md#con-04), with client authentication enabled and the shipped middleware configured.

### Artifact

The gateway's log output, the `/metrics` exposition and the error bodies it returns.

### Response

The gateway shall report request identifiers, fixed outcome codes and durations without the credential values or the message text.

### Response Measure

After the runs, a search of the captured logs, the `/metrics` output and every error body finds zero occurrences of the synthetic provider key, each synthetic client token and each synthetic message.

## QRT-01

Allowed, denied and failing requests with synthetic credentials and messages leave none of those values in the gateway's logs, metrics or error bodies.

- **Status:** Active
- **Level:** CI
- **Runs at:** `tests/test_confidentiality.py` in the `Run tests` step of the `check` job in `.github/workflows/python.yml`, on every pull request and on `main`.

### Procedure

1. Let the `check` job of the Python checks workflow run on `main`.
2. In the `Run tests` step, read the result of `test_allowed_denied_and_failing_requests_expose_no_secret_or_message`.
   It starts the recording upstream and gateway processes with the shipped reference middleware, client authentication, a synthetic provider key and two synthetic client tokens.
   It sends allowed requests on both chat routes; denied requests without a token, with a wrong token, for a model the client may not use and with a blocked term; and failing requests with an invalid body, an oversized body, a failing middleware before and after the provider, and an unreachable provider.
   Every request carries its own synthetic message, and the test searches the processes' output, each gateway's `/metrics` and every error body.

**Pass when:** the test passes, which shows zero occurrences of the synthetic provider key, each synthetic client token, the wrong token and every synthetic message in the captured logs, the `/metrics` output and the error bodies.

## QRT-02

Allowed, denied and failing requests against the staging deployment leave the synthetic values they carry out of its logs, metrics and error bodies.

- **Status:** Active
- **Level:** deployed
- **Runs at:** the staging deployment on the university VM, from a terminal on the VM: `python3 scripts/check_confidentiality.py --gateway $STAGING_URL --project gateway7-staging`.

### Procedure

1. Deploy the commit under test to staging by following [deployment](../../deployment.md#manual-deployment).
2. In a terminal on the VM, in the staging checkout directory, set `GATEWAY7_CLIENT_TOKEN` to a staging client token without printing it, and set `STAGING_URL` to the staging gateway's published loopback address.
3. Run `python3 scripts/check_confidentiality.py --gateway $STAGING_URL --project gateway7-staging`, adding `--provider-key-env <NAME>` when the deployment holds a provider key in the variable `<NAME>`.
   The script sends allowed, denied and failing requests, each with its own synthetic message and a wrong synthetic token, then reads `/metrics`, the error bodies and the gateway's Compose logs written since the run started.
4. Record the commit, the three search counts, the final line and the exit code.

**Pass when:** every request returns its expected status, the logs, metrics and error bodies each report `0 synthetic values found`, and the command exits 0.
