# QR-02: Catch A Broken Gateway Change Without A Provider Account

A developer runs the checks covering the gateway's critical modules from a clean checkout without any provider account, and a change that breaks their contract fails those checks.

- **Status:** Active
- **Characteristic:** Maintainability
- **Sub-characteristic:** Testability
- **Business importance:** High
- **Technical risk:** Medium

## Scenario

### Source

A team member or instructor reviewing a change to the gateway.

### Stimulus

The change alters the behavior of a critical module: the middleware runner `gateway7/pipeline.py`, the HTTP entry point `gateway7/app.py`, client authentication `gateway7/auth.py`, or the provider adapters `gateway7/providers.py`.

### Environment

A clean checkout with only the locked dependencies installed by following `docs/setup.md`, no provider API key, and no network access to any LLM provider.

### Artifact

The automated test suite under `tests/` and the one-command demonstration `demo/run.py`.

### Response

The checks shall run to completion offline and shall report a failure for a change that breaks the critical modules' documented behavior.

### Response Measure

`uv run --locked pytest` and `uv run --locked python -m demo.run` complete within 5 minutes and exit 0 on unchanged `main`, and each exits non-zero when the request-side failure handling in `gateway7/pipeline.py` is changed to forward the request anyway.
