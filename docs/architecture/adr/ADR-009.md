# ADR-009: Use PostgreSQL For Managed Administration In Compose

- **Status:** Proposed
- **Created:** 2026-11-16
- **Updated:** 2026-11-16
- **Containers:** `gateway`, `postgres`
- **Addresses:** [FR-021](../../functional-requirements/fr/FR-021.md), [FR-022](../../functional-requirements/fr/FR-022.md), [FR-019](../../functional-requirements/fr/FR-019.md), [QR-03](../../quality-requirements/qr/QR-03.md)

## Context

The repository owner extended [task #288](https://github.com/iteam7/gateway7/issues/288) to make PostgreSQL the primary database through Docker Compose in [PR #289](https://github.com/iteam7/gateway7/pull/289).
The client lifecycle, credential separation, live publication and content-free accounting boundaries remain those proposed in [ADR-008](ADR-008.md).
The owner subsequently clarified that the application had not been run and withdrew the SQLite-to-PostgreSQL transfer capability; [FR-022](../../functional-requirements/fr/FR-022.md) records that withdrawal.
This record describes the requested implementation without claiming a merge, Customer acceptance or an unrecorded team meeting.

## Considered Options

- **Use PostgreSQL for the managed Compose deployment and retain explicit SQLite support.**
  A database service owns durable state while the existing management interface and client execution path remain shared.
- **Keep SQLite as the only managed store.**
  This preserves the earlier deployment, but does not implement the owner's PostgreSQL request.
- **Initialize PostgreSQL from seed YAML on every start.**
  This would overwrite managed users and usage or restore revoked credentials, so bootstrap runs only on first initialization.
- **Allow several independent gateway workers to share the new database.**
  Database transactions alone do not synchronize cached authorization, active leases or request-rate buckets; that would require another runtime design.

## Decision Outcome

Chosen option: PostgreSQL is the primary managed Compose database, with SQLite retained as an explicitly selected compatibility backend.
`compose.admin.yaml` adds the `postgres` container, a persistent `postgres-data` volume and a database health check before gateway startup.
The service has no published host database port.
The original synthetic demonstration and monitoring stack remain available without managed administration.

Configuration selects PostgreSQL through the environment-reference field `auth.management_database_url_env`, or SQLite through `auth.management_db`, with both together rejected.
The URL and any database password remain server-side credentials; the operator state exposes neither.
The Compose default URL contains no password, and the driver obtains the separately supplied password through its environment.
There is no automatic fallback from a failed PostgreSQL connection to SQLite or to seed accounts.

Both adapters provide the same validated client state and numeric ledger contract.
PostgreSQL creates its versioned `gateway7_admin` schema transactionally, bootstraps configured clients only once into an empty registry, and rejects unknown schema versions or malformed stored values.
Client changes persist atomically before publication to the running gateway; credentials remain digests, and deleted identifiers remain reserved.
Usage preserves exact integer counters and aggregates by client, model and UTC day.

One database session holds an advisory ownership lock for the lifetime of the gateway.
A second gateway using that database fails startup, retaining the existing single-process admission and middleware boundary.
The adapter does not reconnect automatically after losing its session.
Readiness and protected request admission check that connection; a lost connection fails closed rather than authorizing from stale cached state after a new owner can acquire the lock.

The implementation includes no cross-backend transfer command or intermediate database export format.
PostgreSQL starts from its own first-initialization bootstrap, and the explicitly selected SQLite backend retains the same independent startup and persistence behavior.

## Consequences

- **Security / Confidentiality — [QR-03](../../quality-requirements/qr/QR-03.md):** database connection failures use fixed messages without credentials, driver diagnostics or SQL text.
  Stored application data remains client policies, token digests, reserved identifiers and numeric usage; prompt and answer content is outside the storage contract.
- **Deployment cost:** managed Compose now starts and retains a PostgreSQL service and volume.
  Database backups, volume ownership and credential provisioning become part of operating that deployment; an external PostgreSQL deployment may instead supply its own URL and transport policy.
- **Runtime cost:** synchronous transactions and liveness checks add database work to protected requests.
  Connection and statement limits bound ordinary failures, but this change makes no new latency claim or multi-worker guarantee.
