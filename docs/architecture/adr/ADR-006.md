# ADR-006: Export Core-Task Events To OpenPanel

- **Status:** Proposed
- **Created:** 2026-11-07
- **Updated:** 2026-11-07
- **Containers:** `gateway`
- **Addresses:** [FR-015](../../functional-requirements/fr/FR-015.md), [QR-02](../../quality-requirements/qr/QR-02.md), [QR-03](../../quality-requirements/qr/QR-03.md)

## Context

[US-14](https://github.com/iteam7/gateway7/issues/174) needs a countable core task rather than visits to the repository.
Operational counters reset with the gateway and do not describe the task's start and completion as a joined event pair.
The [analytics plan](../../analytics.md) owns the four metrics, their queries and the typed event registry.
This record proposes the implementation for review; it records no Customer decision or verified VM deployment.

## Considered Options

- **OpenPanel HTTP events.** Use its existing event charts and separate projects without adding a product data store.
- **A custom analytics database and dashboard.** Rejected because maintaining a reporting product expands the gateway's scope and duplicates an available backend.
- **Prometheus counters alone.** Rejected for product analytics because scrape aggregates cannot reconstruct the task event pair or its traffic-source field.

## Decision Outcome

Chosen option: send the gateway's two fixed chat events to a self-hosted OpenPanel backend over its authenticated HTTP Track API.
`ANALYTICS_ENABLED` controls a separate exporter; a bounded in-memory queue keeps backend latency off the request path.
Events carry random per-task identifiers and fixed categories, never a user identifier derived from a client token.
The operator owns `ANALYTICS_SOURCE`; the client cannot change it, and production accepts only ordinary traffic.
Each environment uses its own project and credential, and every metric query excludes `source=smoke`.
The backend is an external operating dependency and changes neither the three product containers nor the vision's system context.

## Consequences

- **Security / Confidentiality ([QR-03](../../quality-requirements/qr/QR-03.md)).** An explicit payload schema excludes message content, client identities, model names and credentials; ingestion receives no forwarded client IP or user-agent header.
- **Maintainability / Testability ([QR-02](../../quality-requirements/qr/QR-02.md)).** Injected test sinks and protocol fixtures exercise event pairing, source guards and exporter failures without a real provider or backend.
- **Cost.** Queue overflow, export failures and forced shutdown can lose events; no retry or exactly-once delivery is promised, and the metrics are not a billing or audit ledger.
- **Cost.** A random identifier represents one task rather than a person, so these events cannot measure unique users or retention.
