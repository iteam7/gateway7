# ADR-010: Version Administrative State And Reserve Usage Before Forwarding

- **Status:** Proposed
- **Created:** 2026-11-16
- **Updated:** 2026-11-16
- **Containers:** `gateway`, `postgres`
- **Addresses:** [FR-021](../../functional-requirements/fr/FR-021.md), [FR-023](../../functional-requirements/fr/FR-023.md), [FR-024](../../functional-requirements/fr/FR-024.md), [FR-026](../../functional-requirements/fr/FR-026.md), [FR-027](../../functional-requirements/fr/FR-027.md), [FR-028](../../functional-requirements/fr/FR-028.md), [QR-03](../../quality-requirements/qr/QR-03.md)

## Context

The owner's [task #295](https://github.com/iteam7/gateway7/issues/295) requests the complete administrative and monitoring increment following the audit of merged [PR #289](https://github.com/iteam7/gateway7/pull/289).
The earlier managed client store persists policies and daily observations, but stale browser state can overwrite later permissions, synchronous database work can stall the application event loop, and terminal-only counters cannot reserve concurrent spending.
This record describes the requested implementation; it does not claim a team meeting, Customer acceptance or a merge.

## Considered Options

- **Version control state and append private audit and accounting records in the existing store.**
  Both managed backends retain one owner and share the administrative contract.
- **Publish browser snapshots without a revision check.**
  This leaves stale full-profile edits able to restore permissions an operator has narrowed.
- **Check budgets against terminal totals alone.**
  Several concurrent keys can spend the same remaining allowance before any call finishes.
- **Put database calls directly on the async HTTP path.**
  A slow store then delays unrelated requests and health handling on the same event loop.

## Decision Outcome

Chosen option: one versioned control document, atomic audit entries and durable request reservations, accessed through a bounded database executor.
An administrative write requires the caller's current revision and is rejected with a conflict when another write has committed first.
The database transaction commits the new document, optional client-policy changes and a sanitized actor/action/target/diff audit entry together.
The application publishes the resulting access and policy snapshot without an intervening await.
Owned mutation tasks finish publication after persistence even when the initiating HTTP caller disconnects.

Named client keys and operator credentials are represented by digests with explicit metadata and expiration checks.
Authentication reads the current in-memory snapshot, and write authorization is checked again after body delivery against the current operator role.
The server-configured bootstrap operator remains a recovery capability; ordinary operators have named administrative or read-only roles.

All database work runs away from the application event loop through a bounded, single-worker executor that retains ownership of the store connection.
Shutdown drains owned operations before closing that connection.
The existing one-gateway-per-database ownership rule remains in force; this does not add several independently cached gateway workers.

Before forwarding a budgeted provider request, accounting reserves finite input/output and priced cost bounds atomically across applicable user/model and UTC day/month rules.
Known terminal source usage settles the reservation once; missing usage or an interrupted process retains unresolved reservation amounts rather than silently counting them as zero.
Hard admission rejects an unbounded request or missing required price, while warning rules record their threshold state without denying traffic.
Costs are estimates derived from the captured pricing revision, not provider invoices.

Private request records retain identity, key, model, request start, terminal outcome, durations and numeric accounting without conversation content.
Reports use aware UTC intervals with an inclusive start and exclusive end, bounded pages and streamed exports.
Retention removes detailed history according to the configured policy without resetting active budget accounting or unresolved reservations.
Offline backup and restoration preserve control state, identity digests, encrypted provider credentials, audit and accounting state within the same backend contract.
The withdrawn cross-backend transfer in [FR-022](../../functional-requirements/fr/FR-022.md) remains outside this increment.

## Consequences

- **Security / Confidentiality — [QR-03](../../quality-requirements/qr/QR-03.md):** protected audit and diagnostic records exclude raw tokens, provider credentials and message content.
  Read-only operators cannot invoke mutation routes or obtain generated credentials.
- **Operational cost:** the executor has finite queue capacity, and callers can receive overload or availability errors when it cannot safely accept work.
  Database failure retains the existing fail-closed ownership boundary.
- **Accounting cost:** conservative bounds and unresolved reservations can deny calls before an external account's nominal allowance is exhausted.
  Operators need visible reservation and unknown-usage states; treating unknown source usage as a precise zero would hide this uncertainty.
- **Compatibility cost:** schema upgrades retain earlier client policies and observations, while old daily-only records cannot acquire invented request-start timestamps.
  Legacy observations remain identifiable separately from precise request history.
